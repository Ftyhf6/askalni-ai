أريد منك تجهيز مشروع "askalni-ai" بالكامل اعتمادًا على ملف "AcclaimedAgreeableConfigfiles.zip" الموجود في المشروع.

نفّذ العمل بالترتيب التالي، ولا تتوقف عند أول خطأ:

1. استخراج الملفات

- ابحث عن "AcclaimedAgreeableConfigfiles.zip".
- أنشئ مجلدًا مؤقتًا للاستخراج.
- فك ضغط ZIP بالكامل.
- افحص شجرة الملفات المستخرجة قبل نسخ أي شيء.

2. حماية المشروع الحالي

- لا تحذف أي ملف موجود.
- لا تستبدل أي ملف موجود تلقائيًا.
- قبل أي استبدال، قارن الملف القديم والجديد وحدد الاختلاف.
- احتفظ بالحالة الحالية للمشروع بحيث يمكن التراجع عن أي تغيير.

3. دمج الملفات

- قارن الملفات المستخرجة مع مشروع "askalni-ai".
- أضف الملفات الجديدة المطلوبة.
- إذا كان الملف موجودًا بالفعل، افحص هل النسخة الجديدة ضرورية.
- لا تضف ملفات build أو cache أو ملفات مؤقتة غير ضرورية.
- لا ترفع ".env" أو API keys أو private keys أو كلمات مرور إلى GitHub.

4. فحص إعدادات المشروع

افحص خصوصًا:

- "package.json"
- lockfile المستخدم
- "vite.config.*" أو إعدادات Next.js إن وجدت
- "tsconfig.*"
- ملفات React/TypeScript
- إعدادات Vercel
- ملفات API وbackend
- ملفات المصادقة
- ملفات الدفع والـ Premium
- ملفات AI
- أي configuration files جاءت من ZIP.

5. Dependencies

- حدد dependencies المطلوبة فعليًا.
- ثبّت الناقص فقط.
- لا تضف مكتبات بديلة إذا كانت المكتبات الحالية تؤدي الغرض.
- تأكد من توافق الإصدارات مع المشروع الحالي.

6. Environment Variables

- ابحث عن جميع المتغيرات المطلوبة.
- أنشئ أو حدّث ".env.example" فقط إذا كان مناسبًا.
- لا تضع أي قيمة سرية حقيقية داخل Git.
- أعطني في النهاية قائمة واضحة بالـ Environment Variables التي يجب إضافتها إلى Vercel/Replit.

7. فحص الكود

افحص المشروع بحثًا عن:

- أخطاء TypeScript
- imports مفقودة
- packages مفقودة
- routes مكسورة
- أخطاء React
- أخطاء API
- أخطاء authentication
- أخطاء الدفع/Premium
- أخطاء AI
- مشاكل CORS
- مشاكل build أو deployment.

8. إصلاح الأخطاء

أصلح الأخطاء التي يمكن إصلاحها بأمان، مع الحفاظ على الميزات الموجودة.
لا تعيد كتابة المشروع من الصفر.

9. اختبار البناء

شغّل أمر البناء الصحيح للمشروع.
إذا فشل:

- اقرأ الخطأ الحقيقي.
- أصلحه.
- أعد تشغيل build.
- كرر حتى ينجح أو تحدد بوضوح ما يمنع النجاح.

10. اختبار التشغيل

شغّل التطبيق محليًا واختبر الصفحات والـ routes الأساسية.
تأكد أن الصفحة الرئيسية تعمل وأن التطبيق لا يظهر أخطاء Console واضحة.

11. Vercel

جهّز المشروع للنشر على Vercel.
تحقق من:

- build command
- output directory إن كان مطلوبًا
- environment variables
- routing
- API/serverless functions
- إعدادات framework.

لا تنشئ مشروع Vercel جديدًا إذا كان المشروع الحالي مرتبطًا بالفعل، ولا تغيّر إعدادات الإنتاج دون التأكد.

12. Git

كل التغييرات يجب أن تكون على الفرع:

"add/acclaimed-configfiles"

لا تعمل على "main".

بعد الانتهاء، أعطني تقريرًا واضحًا يحتوي على:

1. حالة استخراج ZIP.
2. الملفات التي تمت إضافتها.
3. الملفات التي تم تعديلها.
4. الملفات التي لم يتم لمسها.
5. أي تعارضات وكيف تم التعامل معها.
6. Dependencies التي أضيفت.
7. Environment Variables المطلوبة.
8. نتيجة TypeScript/lint إن وجدت.
9. نتيجة build.
10. نتيجة تشغيل التطبيق.
11. أي أخطاء متبقية.
12. هل المشروع أصبح جاهزًا للنشر على Vercel أم لا.
